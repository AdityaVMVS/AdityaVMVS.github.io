Introduction

I wanted a small project where I could follow the whole feedback loop, from reading the sensor input to seeing what the output did on the board. The controller compares the voltage it reads with a target voltage and changes the PWM duty cycle to bring the reading closer to that target.

ADC reading→Filter & PID→PWM output→RC circuit

Tools & setup

STM32 Nucleo

The NUCLEO-F767ZI reads the voltage on PA3 (A0) and drives PWM on PA6 (D12). The ST-LINK USB connection carries the USART3 serial traffic on PD8 and PD9.

RC circuit

Two resistors and a capacitor turn the PWM pulses into a voltage that changes gradually. That gives the controller a real circuit to regulate on a small bench setup.

Embedded C & FreeRTOS

CMSIS provides the register definitions. FreeRTOS schedules the control and telemetry tasks.

Python & pytest

The test sends commands over serial and saves the samples and calculated measurements as CSV and JSON.

Project details

From the ADC to the PWM pin

Every 10 ms, a FreeRTOS task starts the ADC and waits for a notification from the conversion interrupt. It smooths the reading with a low-pass filter, runs the PID calculation, and writes the new duty cycle to the PWM timer. I limited the duty cycle to 0–100% and pause the integral when it would push the output farther into either limit.

Keeping serial output out of the control loop

The controller puts its latest reading in a one-slot queue. A lower-priority task handles sending it over UART. If the serial side falls behind, the controller carries on and the sequence numbers show where a frame was missed.

What happens when the input fails

The firmware turns the PWM off if the ADC times out or if the loop runs outside its timing bounds. It also watches for readings stuck near either voltage rail. For a low reading, the controller checks that it was already driving the output so a discharged capacitor at idle can read zero. The output stays off after a fault until the board is reset.

Bench testing

The pytest bench run steps the target voltage up and records the circuit as it responds. It then shorts the ADC input to ground using PF3 (A3) in the HIL build, checks that the controller commands zero duty, and checks that it stays off when the short is released.

  • Latency is the time from the start of sampling to the PWM register write.
  • Scheduling jitter shows how far the time between samples moves away from 10 ms.
  • Overshoot shows how far the feedback voltage rises above the target.
  • Settling time shows how long the feedback voltage takes to enter and stay within a small band around the target.

The firmware builds and Python measurement tests have been checked. Physical bench measurements are still pending.
